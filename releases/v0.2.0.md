# v0.2.0

The holder wire protocol now names the product: every frame starts with `HDRSHLD1` instead of 0.1.0's `HDRKEEP1`. Nothing else changes.

## Upgrading from 0.1.0

This release cannot talk to holders a 0.1.0 binary started. Both sides refuse the other's frames before the version handshake, so `attach`, `list`, `reconcile` and a live-handoff rebind from 0.2.0 cannot reach them, and the connection ends without naming the compatible client.

- **Keep the 0.1.0 executable** while any of its holders runs: each holder keeps running the executable it started from, so install 0.2.0 in its own directory, as the [README](https://github.com/rezzminator/herdr-shield#upgrade-and-uninstall) says.
- **Reach an old holder with the old executable:** `herdr-shield attach <holder-id>` or `herdr-shield kill <holder-id>` run from the 0.1.0 binary.
- **New panes** opened after you point `terminal.default_shell` at 0.2.0 get 0.2.0 holders.

Never kill a holder just to upgrade: it holds a living shell and everything running in it.

The full list of changes is in [CHANGELOG.md](https://github.com/rezzminator/herdr-shield/blob/main/CHANGELOG.md#020--2026-11-01).
