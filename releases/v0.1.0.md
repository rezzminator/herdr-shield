# v0.1.0

The first public release of herdr-shield, a Herdr plugin that keeps your shells, and the coding agents and builds running in them, alive when the Herdr server crashes or restarts.

## What it does

Set `herdr-shield` as Herdr's `terminal.default_shell`, and each new pane's shell runs inside a holder: a transient systemd user service that owns the pane's PTY. When the Herdr server dies, the holder and your shell keep running with the same process, memory and screen. After Herdr is back, `herdr-shield attach <holder-id>` reconnects the living shell and redraws its screen.

- **Nothing is relaunched.** The original process keeps running; there is no snapshot and no replayed command.
- **Nothing is killed by guesswork.** A holder ends only when Herdr closes that exact pane and herdr-shield authenticates the close; a crash, a missing socket or an empty pane list keeps it.
- **Every gap is reported.** `herdr-shield list --json` and the plugin's `list` action show every pane as PROTECTED or UNPROTECTED with its reason, every holder, and each orphan's exact cleanup command.
- **No automatic recovery.** If a holder is lost, a recovery screen shows the captured command and offers Enter only once the original process is proven gone.
- **Safe fallback.** Where a holder cannot be verified, herdr-shield prints UNPROTECTED with the reason and opens your configured plain shell.

## Requirements

- Linux with a running systemd user manager.
- Herdr 0.9.5, integration protocol 22, the release it is tested against (`herdr-shield doctor` refuses any other protocol), with `shell_mode = "non_login"` and `resume_agents_on_restore = false`.
- Rust through rustup, to build from source: `rustup toolchain install` installs the toolchain pinned in `rust-toolchain.toml`.

## Install

This release is source only. Build it, link it as a Herdr plugin, write its configuration and point Herdr's default shell at it; the [README](https://github.com/rezzminator/herdr-shield#install) has every step.

## Known limits

- Only panes started through `terminal.default_shell` are protected; panes launched with an explicit command, and panes already running at installation, are reported UNPROTECTED.
- After a cold Herdr restart, reconnecting is a deliberate `herdr-shield attach <holder-id>`: stock Herdr has no durable pane identity to rebind automatically. A Herdr live handoff rebinds automatically.
- Logout, a stop of the systemd user manager and reboot still end protected shells.
